# План — довести worklog-слой и схемный контракт до целевого вида

> Модель течения данных, на которой всё стоит, описана в `README.md` → *How data flows*. Читать её первой.
> Договорённости (синхронизированы с продактом 2026-08-14):
> - **Черновик (worklog) пишет сабагент** (или сам оркестратор, если сабагентов нет/не разрешили).
>   Оркестратор владеет **реестрами, чистовиком, проекцией, состоянием**.
> - **Продакт подписывает чистовики** (артефакты), не черновики — черновик он обычно не видит.
> - Чистовик = 2 функции: язык для подписи + витрина по шаблону (поэтому нужны ключи колонок).
> Принцип по-прежнему: канон не растёт без нужды; чиним механизмы, из-за которых родятся реальные проблемы.

## Фаза 2 — Схемный контракт: ключи колонок (МОДЕЛЬ УТОЧНЕНА продактом 2026-08-14)

**Скорректированная модель (важно).** Истина формы — **чистовик секции = интерфейс, 1:1**. Форму задаёт
**шаблон шага** (по дефолту = основные тезисы метода). **Черновик (worklog/фрагмент) стремится к той же
форме, но вправе быть шире** — больше таблиц/колонок/деталей, допустимы правки метода и заполнение из сорсов;
тогда **оркестратор адаптирует данные черновика в фиксированную форму чистовика** (форма не гнётся под
черновик). Поэтому **НЕ** сводим фрагменты к шаблонам (большой рефактор отменён) — фрагмент вправе отличаться.

**Три дома ключа (решено продактом 2026-08-14).** Ключи живут ТОЛЬКО в: (1) шаблоне шага — форма-эталон;
(2) чистовике инстанса — что читает интерфейс; (3) реестрах инстанса. **В шаблоне метода
(`template-fragment.md`) ключей НЕ бывает** — его никто не потребляет (оркестратор сопоставляет колонки по
смыслу), а синхронить их при каждом новом скилле — чистый источник ошибок. check O теперь считает ключ в
шаблоне метода ОШИБКОЙ.

Сделано:
1. **Ключи `<!--c:key-->` во все 5 шаблонов шагов** (1,3,4,5,6; 2 был готов) — форма-эталон чистовика/интерфейса.
2. **Ключи из всех 11 шаблонов методов УБРАНЫ** (перенос агентами откатан — находка о расхождении осталась
   ценной). Шаблон метода описывает форму словами/примером, без разметки; вправе быть шире чистовика.
3. **check O переписан**: well-formedness только на шаблонах шагов + сторож «ключ в шаблоне метода = ошибка».
   Убрано требование template==fragment. Канон *Column keys* в CONVENTIONS переписан под три дома.
4. **check O2 — instance-conformance** добавлен: keyed-секция инстанса обязана нести ровно ключи своего
   шаблона. **Enforced-if-present** (немигрированные инстансы молчат). Поймал реальный рассинхрон в шаге 2
   (decksmith вынес assumptions в отд. таблицу, rebuild держал инлайн) → канон = инлайн-форма, decksmith приведён.

Консольный блок (СДЕЛАНО 2026-08-14, selftest зелёный, линтер 0 ошибок):
5. **Реестры по ключу.** `F.ENUMS` → `(allowed, key, aliases)`: канонический ключ колонки матчится
   первым, алиасы EN/RU — только фолбэк для немигрированных. `text.py`: `header_name()` (снимает
   ключ-марку), `column_key_values()` (значения по ключу через все таблицы); `table_column`/`table_rows`
   теперь тоже стрипуют марку при матче по имени. `instance.py._register`: парсит ключи, стрипует
   заголовки, дублирует доступ к ячейке (по имени И по ключу), отдаёт `col_keys`, выбор таблицы — по
   ключу `id` тоже; enum-валидация по ключу первым. `lint.py` check D — тоже key-first. `serve.py` —
   распаковка `(vals, *_rest)`.
6. **Консоль по ключу.** `app.js viewRegisters`: `byKey`/`colOf` резолвят каноничный ключ в реальный
   заголовок (`col_keys` из payload), алиасы — фолбэк; убраны хардкод `enumCol`/`statusCols`. Шаговые
   таблицы уже читались по ключу (`colKey`/`COL_SCHEMA`) — не трогали.
7. **Миграция реестров эталона.** `examples/decksmith/registers/{hypotheses,risks,metric-tree}.md` —
   ключи на адресуемых колонках (`id` + enum), по принципу «нет потребителя → нет ключа» (описательные
   колонки без ключей). Канон *Column keys* → дом №3 уточнён.
8. **Selftest** `tools/loops/selftest.py`: (а) эталон несёт `col_keys` и строка адресуется по ключу;
   (б) RU-реестр с ключами — enum ловит битое значение и колонка находится по ключу, а не по алиасу.

Остаточный технический долг (не бага): если реестр вырастет во ВТОРУЮ таблицу и заключуют только первую,
check D покроет по ключу лишь заключёванную (для сплит-реестра ключевать надо все таблицы). У эталона все
реестры — одна таблица, регресса нет.

## Алиасы удалены полностью (2026-08-14, решение продакта «отказались от их механики»)

Механика «матч колонки по хардкод-списку заголовков EN/RU» убрана целиком — колонка находится только по
`<!--c:key-->`, фолбэка по имени нет; инстанс, который читает консоль, ОБЯЗАН заключевать свои колонки.
- **`F.ENUMS`** → `(allowed, key)` (третий элемент-алиасы удалён). `instance.py._register`, `lint.py` check D,
  `serve.py` — читают строго по ключу; нет ключа у обязательной enum-колонки → WARN «нет колонки с ключом».
- **`app.js`**: реестровый рендер (`colOf` без алиасов) + все прямые `cell(r,'x','ru')` в обзоре/метриках/борде
  → чтение по каноническому ключу (работает за счёт дублирования ячейки по ключу в `_register`). Шаговые
  таблицы: убраны прозаические `needles` из `colKey`-вызовов и мёртвый `colIdx`; остался mark → `COL_SCHEMA`
  (позиционный, язык-независимый — не алиас). STR-подписи интерфейса (i18n) не трогали.
- **Потребляемый набор ключей в реестре шире, чем id+enum:** консоль читает по имени ещё `hypothesis`,
  `definition`, `unit`. Оба эталона (decksmith и decksmith-rebuild) заключёваны полностью; канон
  *Column keys* дом №3 расширен. `header_name()`/`column_key_values()` в `text.py` — общие примитивы.
- Остаётся к ребилду/Фазе 3: когда чистовики инстанса получат ключи, позиционный `COL_SCHEMA` тоже уйдёт —
  `colKey` станет чистым mark-lookup.
